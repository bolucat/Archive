## BoxPlayer v5.0.16

### 多网盘文件操作 / Cloud-drive File Operations

- 修复 Dropbox 在子目录中新建文件夹或文本文件时丢失目录路径、错误创建到根目录的问题，并补充同名文件/文件夹的清晰提示。
- 修复光鸭云盘的目录识别、签名下载地址解析和上传流程：使用服务端返回的表单上传凭证，不再自行构造不匹配的 OSS 签名。
- 修复 139 云盘备用路由重试逻辑，业务校验或权限错误不再被后续 404 覆盖；新建文件夹按接口要求提交名称与冲突策略。
- 修复 123 云盘新建文件夹响应中 `dirID` 的识别，并移除开放 API 未支持的“彻底删除回收站文件”调用。
- 修复百度网盘移入回收站的异步任务结果识别；已正确创建任务时不再误报失败。

### 菜单与能力边界 / Menu and Capability Boundaries

- 搜索、最近文件、收藏、回收站及 Google Drive 共享虚拟目录不再显示上传、新建文件或新建文件夹等写入操作。
- 115 与 Box 的普通文件页不再显示不支持的直接彻底删除；需要先移入回收站。123 云盘也会明确提示其开放 API 的限制。
- 百度、Dropbox、天翼云盘等已接入“移入回收站”能力的网盘会正确显示该操作；未接入回收站管理的能力不会被误展示。
- 首次打开网盘目录时会及时同步当前目录状态，避免工具栏在数据加载前错误判断目录能力。

### 书籍与下载 / Books and Downloads

- 书籍文本预览读取第三方网盘下载链接时，会保留该网盘所需的请求头；不再被阿里云盘请求拦截逻辑错误阻断。
- Dropbox 缩略图请求移除非官方参数，提升兼容性。

### English

- Fixed Dropbox folder and text-file creation inside subfolders by preserving the provider path, with clearer duplicate-name errors.
- Fixed Guangya directory detection, signed download URL parsing, and uploads by using the server-provided OSS form policy instead of generating an incompatible signature.
- Improved Cloud 139 request fallback and folder creation, fixed 123 Pan folder-id handling and removed its unsupported permanent-delete request, and recognize successful Baidu recycle-bin tasks.
- Virtual search, recent, favorite, recycle-bin, and Google shared locations now hide write actions. Provider menus no longer expose permanent deletion or recycle-bin actions the provider does not support.
- Third-party cloud book previews preserve required download headers, preventing Aliyun-only request guards from blocking legitimate provider URLs.
